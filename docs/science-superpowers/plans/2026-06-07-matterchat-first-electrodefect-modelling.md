# MatterChat-First Electrodefect Modelling Analysis Plan

> **For agentic workers:** REQUIRED SUB-SKILL: pre-register this plan with science-superpowers:preregistering-analysis BEFORE execution. Then use science-superpowers:subagent-driven-analysis (recommended) or science-superpowers:executing-analysis to run it step-by-step. Steps use checkbox (`- [ ]`) syntax for tracking.

**Question:** Can geometry-vetted W/Mo Frenkel-pair defect structures support a defect-recombination route to hot carriers, with MatterChat used only when its qualitative feedback is structure-specific, non-empty, and testable?

**Design:** Staged computational validation: MatterChat qualitative annotation on QC-passing structures, followed by independent geometry repair, MLIP screening, DFT energetics/emission proxies, transport/localization diagnostics, and optional TDDFT cross-check.

**Data:** W/Mo clean, separated, and recombined BCC slab CIFs generated by `scripts/29_matterchat_geometry_qc.py`; current input run is `runs/matterchat_geometry_qc_20260607_022909`.

**Primary analysis:** Evidence-chain gate across geometry, DFT recombination energy, escape budget, static emission proxy, and transport/localization diagnostics. MatterChat feedback is an advisory input only if it passes the response-quality gate below.

**Decision rule:** H1 is supported only if the physics chain passes all required gates: no blocked geometry, converged DFT energetics, positive escape budget under fixed assumptions, emission contrast above the existing project gate, and confirmatory transport from DFT-derived Hamiltonians. MatterChat can shape candidate annotations only if its responses pass quality checks; empty, generic, or hallucinated MatterChat output is treated as non-admissible feedback rather than agreement with the plan.

- [ ] **Step 1: Select candidates**

Select separated structures first because they carry the Frenkel-pair state. Include the matching recombined control for every selected separated structure. If MatterChat responses fail the quality gate, select candidates from the pre-specified material/morphology grid rather than from MatterChat motif ranking.

- [ ] **Step 2: Run MLIP relaxation as screening only**

Relax selected structures with MACE or CHGNet using fixed bottom-contact constraints. Record calculator, model version, force threshold, step count, and final minimum pair distance.

- [ ] **Step 3: Validate repaired geometry**

A structure can proceed to DFT only if:

- finite positions and cell;
- same intended material and atom count as its starting CIF;
- minimum pair distance `>= 1.8 A` after relaxation, or a written justification that the short distance is a stable dumbbell motif;
- no atom collapse into vacuum;
- no change from separated to recombined topology unless the event is explicitly recorded as relaxation-induced recombination.

- [ ] **Step 4: Classify geometry outcome**

Classify each candidate as:

- `promote_to_dft`: passes geometry validation;
- `matterchat_only`: useful for qualitative annotation but not DFT-ready;
- `blocked_geometry`: failed validation or collapsed.

## Task 3: DFT recombination energetics and work-function labels

**Artifacts:**

- [ ] **Step 1: Prepare paired separated/recombined labels**

For every promoted separated structure, identify the exact recombined control with the same material, morphology, slab size, and boundary setup.

- [ ] **Step 2: Run BigDFT CPU labels first**

Use BigDFT CPU for the conservative label path. Record infocode, convergence warnings, total energies, finite-temperature settings, density/potential outputs, and any missing artifacts.

- [ ] **Step 3: Run QE GPU cross-checks only on geometry-clean cases**

Use QE 7.5 GPU only after the geometry validation gate passes. Record pseudopotential path, cutoff, k-grid, smearing, convergence status, and warnings.

- [ ] **Step 4: Compute recombination energy**

For each valid pair, compute `E_FP = E_separated - E_recombined` using only converged labels with matched settings. Mark pairs with non-converged or mismatched labels as `blocked_dft`.

- [ ] **Step 5: Apply DFT gate**

Classify:

- `dft_supported`: matched labels converge and `E_FP` is finite and physically interpretable;
- `dft_partial`: one code path converges but warnings or code disagreement remain;
- `blocked_dft`: non-convergence, mismatched settings, NaN, or unresolved warnings.

- [ ] **Step 1: Lock escape-budget assumptions**

Before calculating outcomes, record `phi_eff`, `n_hop`, `E_hop`, and the allowed loss scenario set. Use the repo default `phi_eff = 4.55 eV` as the W baseline unless a converged work-function label replaces it.

- [ ] **Step 2: Compute escape budget**

Compute `E_escape = E_FP - n_hop * E_hop - phi_eff` for every DFT-supported pair and every pre-specified loss scenario.

- [ ] **Step 3: Compute static emission proxy**

Use existing emission code only on converged DFT artifacts. The project gate remains `emission_contrast(clean, recombined) > 5`.

- [ ] **Step 4: Apply emission gate**

Classify:

- `emission_supported`: positive escape budget in the primary loss scenario and emission contrast `> 5`;
- `energy_only_partial`: positive escape budget but missing or failed LDOS/emission proxy;
- `blocked_or_negative`: non-positive escape budget, missing DFT artifacts, or emission contrast `<= 5`.

## Final evidence classification

Classify the overall result as:

- `strong_support`: MatterChat suggestions were admissible, and geometry, DFT, escape, emission, and real-Hamiltonian transport gates all pass.
- `partial_support`: at least one physics link passes, but another remains missing, warning-limited, or proxy-only.
- `negative`: required gates run cleanly and contradict the electrodefect chain.
- `blocked`: geometry, convergence, missing Hamiltonians, or missing artifacts prevent interpretation.
